适用于数据准备、标注和定稿记录。目标是让读者先看清产出、保留理由和主要损失，再按需追溯执行细节。文档维护与路径分别遵循[研究笔记规则](research_notes.md)和[产物组织](artifacts.md)。

## 报告开头：结果与两条筛选链

开头用三至五条结论说明实际完成范围、最终可用规模、主要瓶颈、质量结论与下一步条件，附正式数据入口。计划规模与实际规模分列；中间候选不计作正式交付。

| 必须回答的问题 | 最小记录 |
|---|---|
| 为什么是这些来源？ | 来源与排除范围、划分和稳定选样顺序；扫描数、实际检查数、保留数，以及各淘汰原因和未处理数量 |
| 为什么这些内容合格？ | 长度、边界、来源隔离等实际准入条件；内容主题或 OCR 等描述标签与筛选理由分开 |
| 如何形成最终数据？ | 生成、程序检查、语义核验、去重、复核、配额和写出的输入／通过／减少数；减少原因及证据入口 |
| 为什么仍有样本失败？ | 按文档或轨迹统计互斥结果标签；若要求逐段配额，说明短缺段数和缺额，不能只报总题数 |
| 合格意味着什么？ | 区分格式通过、模型核验通过、抽样复核和实际任务效果；给出复核分母、错误类型及正式数据位置 |

表格优先采用“阶段／原因标签／数量与分母／简短解释”。正文解释最大的损失和一两个代表案例，不粘贴逐条响应或完整配置。

## 原因标签与统计口径

- 标签描述实际规则或可观察问题，例如 `length_failed`（长度不足）、`boundary_failed`（切分失败）、`question_ambiguous`（问题有歧义）、`duplicate_fact`（同事实重复）、`quota_shortfall`（配额不足）。保留也要说明满足哪些条件，避免笼统写“质量好”。标签按实际需求选用，不要求预置全部类别。
- 同一统计表采用一个主原因；多原因时按已声明的处理顺序或优先级归类，使“输入＝保留＋淘汰＋未处理”可核对。补充描述可以多标签，但明确不能相加。未达检查预算、未完成请求和真正不合格分别记录。
- 保留原始原因与样本 ID 的关联。对已有自然语言理由做事后归类时，注明归类口径、来源及不确定项；不能把事后内容描述写成当初选样条件。原记录不足时明确缺失，不补造标签。
- 文档、窗口、QA、不同事实和完整轨迹分别计数。跨单位转换要解释，例如一个事实的多种问法只留一题；通过核验但来自失败轨迹的题与因质量淘汰的题分开。
- 每个比例写出分子、分母与阶段。全流程产率、某阶段通过率和固定面板错误率不可混用。全局数量足够不能抵消局部配额；“首次出现缺额的阶段”只描述处理过程，不等同于因果归因。
- 有补题时分别记录首轮、补题后和终审后的达标数及分母；按轮记录缺额、生成数、新增不同事实、净变化和额外用量。记录停止原因与累计轮数，运行中断和预算耗尽的数据失败分开统计。
- 复核记录抽样范围、抽样方法、模型／人工、重复覆盖情况、处理前后规模及裁决依据；删题和合并后重算配额，保留原面板结果。QA 接受与诊断模型是否答对分别统计。

## 报告后部：执行依据与追溯入口

| 内容 | 保留方式 |
|---|---|
| 可复现设置 | 来源 revision、seed、划分、窗口与配额规则、配置和 prompt 快照、实际模型及软件信息；长配置和命令用链接 |
| 执行与恢复 | 已完成／未完成阶段、实际执行位置、失败与重试、续跑入口；规则调整注明新批次，保留原结果 |
| 质量与样例 | 有／无证据诊断及其分母、错误类型、一个成功和少量失败样例；不能据仅问题答对直接推断泄漏 |
| 用量与耗时 | 新逻辑请求、网络尝试、缓存复用、实际 tokens、缺失 usage；并发请求耗时之和与墙钟时间分开，按处理样本和成功样本分别摊销，说明统计覆盖范围 |
| 产物索引 | 正式数据、原始来源引用、中间决策、请求缓存、源码／配置和报告；按用途分组，不在开头展开文件清单 |

交付前核对阶段收支、分母、正式文件与报告的一致性和本地链接。细粒度原始记录已有时直接引用，不为报告再复制正文或另设持久化格式。
