## 2. 预训练链路

每个 episode 包含一份原文片段 $X$ 及其紧邻续写 $Y$。写入流为 $X$，两个 read 在写入结束后执行，分别监督重建 $X$ 和续写 $Y$。来源保存文档标识、URL、抓取日期、原文字符范围、句子索引与切分方式。

基础候选包含段落、随机连续句子组、单句和相邻段落组合。超长段落沿句界划为合法片段。主题标注缓存使用一个 JSON 对象，按文档 ID 记录 `model` 和 `ranges`；`ranges` 为覆盖全文句子序列的连续左闭右开索引区间。程序按索引提取原文并检查顺序、范围和覆盖。

FineWeb 原始 Parquet 保存在 `data/raw/HuggingFaceFW-fineweb/sample-10BT/`，`prepare_data --dataset-dir` 指定仓库目录，按配置的子集直接分批读取，受 `--max-documents` 限制；同源页面先分配 train/dev/test，重复原文在构造片段前去重。`preparation.json` 记录语料与子集、tokenizer 配置、预处理契约与统计。模型训练按文档循环访问，再采样粒度和片段，每次访问重新采样容量。

容量按 $K=\min(K_{\max},\max(K_{\min},\lceil |X|/r\rceil))$ 计算，$r\in\{2,4,8\}$。候选去重后过滤写入与两项读取的完整上下文预算。首次写入从空记忆分配 $K$ 个零内容位置，加入固定位置表示，经联合更新得到一份记忆，两项任务共用该记忆。

每个任务先对自身目标 tokens 求平均 NLL，再乘任务权重；batch 按样本平均。跨 microbatch 的梯度按实际样本数累计。语言模型基座冻结，写入时关闭读取 LoRA，读取损失保留到记忆的梯度。

## 3. 评估与恢复

独立文档面板在不同 checkpoint 间保持固定，同一 $(X,Y)$ 在所有合法容量下分别重新写入。错误记忆来自另一个来源，容量与当前条件一致，优先选择长度接近的文本。

评估面板按粒度和输入长度档位轮流选择独立文档。初始化记录第 0 步指标；`eval_generation_every` 控制自由生成频率。批量生成采用左侧 padding，输出完整匹配与正文 token 的归一化编辑距离。独立评估的 `--examples` 和 `--generation-examples` 用于配置最终检验规模。

评估输出 AE token NLL、token accuracy、自由生成序列匹配和 LM NLL/PPL。主要 NLL/PPL 按原文目标 tokens 计分，EOS 另列，附含 EOS 的 NLL。指标按粒度、输入长度、容量、实际压缩率和切分方式分层。逐读取记录实际记忆字节数，训练日志记录累计 token 监督量、文档覆盖、吞吐和峰值显存。

模型 checkpoint 字段为 `phase, config, model_state, optimizer_state, progress, rng_state`。预训练阶段保存读写模块和容量网络参数，优化器更新读写参数。恢复绑定数据准备标识与样本池，恢复文档访问顺序、粒度和容量随机状态以及课程 step。每次启动产生独立日志分段，保留中断前的记录。

## 4. 本地验收与真实数据实验

本地工程验证通过 49 项 v1 与根项目回归测试，服务器通过 43 项 v1 测试；Ruff 检查与格式检查通过。当前测试记录位于 `artifacts/v1/experiments/pretrain-generalization-20260908/local-tests.xml` 与 `server-tests.xml`。

本地使用标准 Transformers/PEFT 构造、保存并加载 tiny Llama，以接口样例验证程序行为。核心验收包括：

1. 空状态、任意合法首次容量、零初值、新旧位置联合更新和 BF16 状态。
2. 变长批量与逐条计算一致，句内上下文有效，写入特征独立于读取 LoRA。
3. 目标 token 的因果对齐，以及损失到写入投影、更新器、读取投影和读取 LoRA 的梯度路径。
4. 原文与续写邻接、来源划分、重复文本去重、主题索引和容量预算。
5. 完整预训练、独立多容量评估、保存恢复；恢复后与连续运行的下一步参数、优化器、采样进度和验证结果完全一致。

FineWeb `sample-10BT` 已经用户授权，使用服务器镜像直连下载完成。真实数据验收进度如下：

1. 512 篇文档完成多粒度准备，产生 6,972 个训练样本、447 个验证样本与 290 个测试样本，输入长度覆盖 1–1,024 tokens。
2. Llama-2-7B-Chat 在物理 GPU 0 完成第 1 步训练、保存和评估，再从保存点恢复至第 2 步并完成评估。
3. 物理 GPU 1 使用固定 16 个真实样本完成 100 步小样本试验。固定训练面板的 AE/LM 正确记忆 NLL 从 3.1738/3.0166 降至 0.1613/0.0278；选取的 66-token 训练片段在三个容量下均完整重建。
4. 独立文档多容量、空记忆和错误记忆对照已完成。dev 的正确记忆 NLL 上升，下一轮重点为扩大文档覆盖、检查网页短行比例及验证泛化收益。

变长 GPU batch 已覆盖 1 与 1,024 tokens、1 与 512 个记忆位置的联合训练。缓存生成与完整前缀读取的一致性回归测试通过；质量报告采用修正后的生成路径。

GPU 训练和评估显式设置 `CUDA_VISIBLE_DEVICES=0` 或 `1`。运行命令见 [项目 README](../../README.md)。

扩大数据实验增加句段筛选、基座流畅度过滤、文档配额与分层数据审查；本地 49 项、服务器 43 项回归测试通过，真实 7B 批量重建回归通过。10,000 篇训练文档生成 126,278 个样本对，dev/test 各包含 512 篇独立文档；两组各 2000 步预训练已完成，dev 选择 3e-5 第 2000 步 checkpoint。512 文档独立 test 已完成，AE/LM 正确记忆 NLL 为 2.2532/2.3914，相对空记忆收益为 0.1409/0.1242。64 文档、三个容量的自由重建完整匹配为 0/192，平均归一化 token 编辑距离为 0.9391；近期实验重点为单次记忆的原文重建和容量利用。运行与验证安排见 [扩大数据预训练记录](20260908_fineweb_generalization_pretraining_record.md)。

SwanLab 接入覆盖训练和独立评估；离线记录及恢复保持模型训练结果一致，云端续接已用 100 步历史日志验证。看板与运行方式见 [项目 README](../../README.md)。

## 5. 后续阶段

MSC 动态训练继承预训练读写参数，按实际 turn 先读取旧记忆预测人工回复，再写入已完成轮次。首次容量使用配置，后续按固定或随机增长计划更新；短轨迹完整 BPTT，长轨迹在完整读写操作边界执行 TBPTT，并在 episode 末更新参数。

容量学习固定完整读写参数，从同一状态展开合法增长动作，使用相同后续文本、读取目标与参数计算质量和资源代价，训练价值网络。独立轨迹比较固定容量、预设增长与学习增长的连续运行收益，开发配套系统对照及长程评估。
