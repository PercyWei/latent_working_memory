## 1. 实验问题与设置

本次实验检验单次写入的记忆读写能力能否泛化到独立文档。两组从同一语言模型基座与相同附加模块初始化开始，使用相同数据访问、粒度和容量采样顺序，以学习率作为组间变量。

| 项目 | 设置 |
|---|---|
| 基座 | Llama-2-7B-Chat，原始权重冻结 |
| 可训练模块 | 写入投影、记忆更新器、读取投影、读取 LoRA，合计 25,467,392 个优化器参数 |
| 学习率与设备 | A：1e-4，物理 GPU 0；B：3e-5，物理 GPU 1 |
| 数据配额 | 10,000 个训练文档，dev 与 test 各 512 个独立文档 |
| 任务与容量 | AE/LM 权重 1:1；2/4/8 压缩率与原有 1000 步容量课程 |
| 输入与续写 | 自然边界，长度上限分别为 1024、256 tokens |
| 更新预算 | 每组 2000 步；microbatch 2，梯度累积 4；每组 16,000 次文档访问 |
| 保存与验证 | 每 250 步保存，固定 128 个 dev 文档进行多容量评估 |
| 自由生成 | 第 0、1000、2000 步，固定 64 个 dev 文档，各覆盖全部合法容量 |

配置位于 [`generalization_lr1e4_a800.json`](../../configs/v1/generalization_lr1e4_a800.json) 与 [`generalization_lr3e5_a800.json`](../../configs/v1/generalization_lr3e5_a800.json)。数据顺序由 seed 20260907 确定，模型初始化使用 seed 42。

## 2. 数据质量与来源

原始数据来自服务器已下载的 `data/raw/HuggingFaceFW-fineweb/sample-10BT/`。准备过程按 seed 打乱文件及 row group 顺序，交替读取各文件的批次并打乱批内文档，从中形成 18,000 篇候选文档。

质量筛选包括以下操作：

1. 保留英语且语言置信度至少为 0.8 的文档，筛除登录、注册、购物车、隐私政策等模板页面。
2. 原文按段落和句界解析；边界检测时屏蔽双引号的保护作用，字符范围仍指向原文，使引号内的多句话可以分别成为自然句子。
3. 筛除缺少结束标点、含省略号截断迹象、网页操作提示、引用列表、版权及交易模板、代码或 HTML 残留、过度重复的句段。完整短句保留；高密度商品或博彩推广关键词用于识别堆砌页面。
4. 每个输入 $X$ 及紧邻续写 $Y$ 位于连续的合格句段内。原始字符区间与拼接后的 $X+Y$ 完全对应。
5. 对文档 ID、归一化来源 URL 和完整原文去重；至少 32 tokens 的相同输入片段在不同来源间去重，同一文档的粒度视图保留。
6. 冻结基座对原文计算平均 token NLL，筛选阈值为 3.3。短文完整计分；长文取开头 512、中部 256、末尾 256 tokens 计分。训练片段继续使用自然句界。该分数是流畅度筛选信号，对罕见词汇和文体存在偏好。
7. 助手执行两轮分层抽查，各覆盖 200 个样本对，补充复核覆盖 32 个样本对；长片段检查首尾及续写边界，分别识别 6、30、7 篇存在拼接、截断、严重改写或网页模板问题的来源，累计剔除 43 篇。排除清单记录文档 ID、对应审查文件及具体理由。修订后的规则应用于全部候选文档，再补齐配额并重新执行来源与连续性检查。

流畅度阈值参照 512 篇校准文档确定：原文 NLL 的中位数为 2.345，95% 分位约为 3.242。抽查中部分推广模板和拼接页面的 NLL 低于 2，因此流畅度分数与结构规则、来源审查共同承担筛选。分数与排除理由保留在实验目录；所有重建和续写目标直接取自 FineWeb 原文。

页面按归一化 URL 的固定哈希分配 train/dev/test。最终数据目录为服务器项目的 `data/v1/fineweb-generalization-20260908/`；`preparation.json` 记录筛选设置、来源、配额、实际样本量与长度分布。

最终训练、dev、test 分别包含 10,000／512／512 篇文档及 126,278／6,488／6,598 个样本对。18,000 篇候选中，流畅度筛选排除 729 篇，助手抽查排除 43 篇；后续结构规则和来源划分构成最终数据。全部输出样本通过原文连续性检查，来源 URL 在三个划分之间互斥，跨来源的相同输入片段在至少 32 tokens 的范围内完成去重。

最终 dev 自由重建样本复核发现 2 篇来源仍含会员优惠推广或网站使用条款。针对这两种已观察到的表述，对完整 train/dev/test 样本对进行定向短语统计，分别命中 0／2／0 篇来源；具体上下文保存在 `residual-quality-audit.json`。该统计描述已发现表述的漏检范围，整体低质量比例仍需独立随机审查估计。本轮训练数据与评估面板固定，后续数据准备可将已确认的模板表达纳入筛选。

预生成训练视图中，2–32、33–128、129–512、513–1024 tokens 分别有 37,220、63,383、24,612、1,063 个。长于 512 tokens 的视图占约 0.84%；实际训练按文档和粒度采样，访问长度分布另由 SwanLab 记录。分层验证用于判断较长片段是否需要增加训练曝光。

## 3. 评估与工程验证

dev 面板按文本粒度及长度档位轮流选样，每个文档贡献一个片段，固定面板在各 checkpoint 和两组实验之间共享。每个片段比较正确记忆、空记忆、其他来源的同容量记忆，分别报告 AE 与续写的 NLL、PPL、token accuracy 和记忆收益。

AE 自由生成按长度分组，每批最多 8 个输入，左侧 padding 支持不同容量与提示长度。完整匹配包含 EOS；归一化 token 编辑距离在正文 tokens 上计算，以预测与参考长度的较大值为分母，再对生成样本求平均。该距离取值为 0–1，较小表示重建错误较少。

初始化完成后记录第 0 步验证；自由生成频率由 `eval_generation_every` 控制。独立评估入口支持 `--examples` 与 `--generation-examples` 指定面板规模。两组训练完成后，在已保存的训练 checkpoint 中，以正确记忆条件下 AE 与 LM 的等权 dev NLL 均值最小为选择标准，并结合相对空记忆、错误记忆的收益判断记忆是否得到利用。选定 checkpoint 在 512 个 test 文档上检验 NLL，另取固定 64 个文档评估自由重建。

本地 49 项测试、服务器 43 项 v1 测试通过。回归覆盖原文连续性、完整短句、引号内句界、文档配额、独立分层面板、批量生成与单条生成一致性，以及保存恢复。真实 7B 回归使用旧试验的同一个 66-token 片段，批量生成在 $K=9,17,33$ 下均与参考逐 token 一致。
