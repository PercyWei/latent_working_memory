## 2. 当前构造与抽查流程

当前实现与执行命令统一见 [独立 AE/LM 数据构造实现](20260909_independent_ae_lm_data_preparation.md)。主流程按以下顺序执行：

1. 读取固定 FineWeb 候选池，检查来源字段和最短文本长度。
2. 按来源及近重复关系去重，建立 semantic/random 共用的 train/dev/test 登记表。
3. 构造 semantic 的完整句界 AE 与内部续写 LM 候选，由强模型判断最终 X/Y，去重并补足各 split 的等量任务配额。
4. 统计 semantic 入选后的任务内输入长度区间，指导 random 独立构造。模型沿用共同内容标准，接受随机边界片段，按任务及区间补足入选数量。
5. 验证原文跨度、来源隔离、容量、配额和长度区间分布，写入固定数据的完成记录。

`inspection.py` 在数据完成后独立执行 `sample → judge → summarize`，也支持人工填写复核结果。随机面板用于观察总体样本质量，分层面板按任务、粒度和长度定位问题。抽查模型使用单独的提示词与缓存协议重新判定；发现系统性缺陷后调整构造配方，再生成下一份数据。

汇总分别记录 pass、fail、uncertain 与未复核数量；存疑或未复核样本通过缺陷比例上下界表达。同一模型的抽查仍可能重复原有判断偏差，人工复核可帮助识别这类问题。

## 3. 实现与验证

评分客户端以直连 HTTP 调用独立服务，关闭 thinking，要求结构化 JSON，并缓存完整样本及评分协议。接口错误、输出截断或格式不合格会使当前构造阶段失败。数据完成后的模型抽查逐批保存结果，支持继续处理未复核样本。

本地 v1 的 65 项测试与 Ruff 检查通过。验证覆盖两类候选构造、模型判定后的配额补足、共享来源隔离、实际输入长度区间、HTTP 协议与缓存、独立抽查和失败完成标记。接口测试使用本地测试服务；真实 Qwen 评分质量、吞吐和正式数据产量在部署阶段验证。
