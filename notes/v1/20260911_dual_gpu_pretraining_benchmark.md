## 设置与计时

使用物理 GPU 0、1，semantic 和 random 的 11,000 步 checkpoint，BF16，每卡 microbatch 2，关闭梯度检查点。正式训练保持暂停。单卡全局 batch 8 累积 4 次；双卡全局 batch 8 累积 2 次；双卡全局 batch 16 累积 4 次。

测试入口 `src/latent_working_memory/v1/distributed_benchmark.py` 实现同步数据并行：每卡保留完整模型，按长度交错分配全局 batch；损失按全局 AE/LM 样本数归一化，累积完成后以 NCCL SUM 合并梯度，再裁剪和更新。全局未使用参数保持 grad=None。此基准采用一次集中梯度同步，尚未采用 DDP 分桶通信与反向计算重叠，因此结果代表当前实现。

每个配置预热 2 步。全局 batch 8 计时 32 步，batch 16 计时 16 步，均计时 256 个样本。计时包含前向、反向、梯度同步、裁剪、优化器更新，以两卡最慢耗时为准；模型加载、CPU 样本准备和评估在计时之外。单卡与双卡 batch 8 使用完全相同的全局样本序列；batch 16 的预热样本数不同，计时区间有偏移，其吞吐比较属于短程近似。

长样本压力测试分别选取输入最长的一个全局 batch 的 AE/LM 样本，并使用压缩率 2。峰值为各卡 PyTorch allocated 的最大值，驱动占用还包括缓存、CUDA/NCCL 上下文；所选 LM 样本不保证同时覆盖最大目标长度。

双卡 batch 8 相对单卡加速 1.54 倍（semantic）和 1.63 倍（random）。双卡 batch 16 相对双卡 batch 8 的样本吞吐提高约 13% 和 9%；相对单卡提升约 1.74 和 1.78 倍。两卡等待、梯度同步及变长样本负载差异限制了扩展效率；同步计时包含等待，不能单独解释为网络传输耗时。

所有配置完成计时和长样本测试，loss 与梯度均有限。两卡重复更新后的参数最大绝对差均为 0。单/双卡 batch 8 每步输入及目标 token 数一致，loss 最大绝对差分别为 0.00287、0.01066，数值结果存在批处理差异。一次 semantic 双卡测试中分配器出现过显存分配重试警告，进程最终成功；allocated 峰值不能代替驱动总占用或所有样本组合的上界。

## 结论与产物

优先缩短单个实验等待时间时，推荐双卡、每卡 microbatch 2、累积 2、关闭梯度检查点，全局 batch 保持 8。全局 batch 16 在显存上可行，但正式采用时需要明确样本/token 预算和优化设置，不能与 batch 8 简单按相同步数比较。两个独立实验同时推进时，每卡各跑一个通常具有更好的总 GPU 利用效率；最终取舍还需计入评估和任务调度开销。
