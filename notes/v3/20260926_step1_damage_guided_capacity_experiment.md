# 20260926_第一步：旧信息损害驱动扩容实验与实现方案

创建时间：20260926 16:21:29 UTC+08:00
最后修订时间：20260929 11:41:07 UTC+08:00

本文具体化 [v3 研究问题](20260923_v3_framework.md) 的第一步：**依据少量历史 QA 观测到的覆盖损害，是否能比表示变化更有效地分配记忆容量？** 门控 QA 的标准答案用于构造离线损害依据；有限 QA 不能覆盖全部旧信息，本步也不主张已经得到可部署的决策器。

总纲中的“固定频率”和“统一扩容次数”是早期设想；第一步的具体对照与容量统计以本文为准。

## 1. 统一设置与比较对象

### 1.1 基本概念与五种方法比较

- **记忆形式**：只研究 token memory，即用连续向量保存压缩内容。每个记忆块有 $k$ 个维度为 $d$ 的 slots，块大小为 $k\times d$。
- **文本范围**：长文本按固定规则分为 $X_1,\ldots,X_T$。ICAE-single 一次处理完整历史，其余方法逐段处理。
- **历史记忆**：记 $M_{t-1}=[P,A]$，其中 $A$ 是最后一个记忆块，$P$ 是更早的记忆块。
- **动态更新**：覆盖指替换 $A$、保持容量；追加指保留全部旧块、增加一个新块。首段只建立初始记忆，不作扩容判断。

| 比较对象 | 压缩方式 | 记忆更新与容量 | 比较作用 |
|---|---|---|---|
| [ICAE-single](https://arxiv.org/html/2307.06945) | 完整历史一次压缩 | 一次得到 $k$ slots | 完整历史单次压缩参考 |
| [ICAE-multi](https://arxiv.org/html/2307.06945) | 各段独立压缩，再拼接记忆 | 旧块不变，共 $Tk$ slots | 独立分段压缩的长文本基线 |
| [AutoCompressors](https://arxiv.org/html/2305.14788) | 结合累计历史记忆压缩新段 | 每段追加，旧块不变，共 $Tk$ slots | 利用历史上下文的逐段追加基线 |
| 按记忆变化扩容 | 根据覆盖候选与旧末块的表示变化决定动作 | 覆盖末块或追加，容量可变 | 检验表示变化能否有效指导扩容 |
| 按信息损失程度扩容 | 根据覆盖造成的旧信息损失及追加收益决定动作 | 覆盖末块或追加，容量可变 | 检验信息损失依据是否能改善容量分配 |

两种动态方法只在末块上覆盖或追加，更新思路更接近 [DLA](https://arxiv.org/html/2606.10650v1) 的 “合并当前状态／新开状态”；[RMT](https://arxiv.org/html/2207.06881) 每轮改写同一份固定容量记忆，AutoCompressors 则每轮追加。这里借鉴更新思路，不复现 DLA 的线性状态计算。

### 1.2 统一框架与方法细节

五种方法从同一预训练 checkpoint 出发，采用以下读写框架，**分别训练，不共享训练后的参数**。

| 部分 | 设置 |
|---|---|
| 写入端 | 冻结基座参数，启用并训练 LoRA；各方法的单套 LoRA 使用相同结构与秩，输入范围由方法决定 |
| 读取端 | 使用同一基座、不启用 LoRA，参数冻结；训练时仍允许损失经读取端回传到记忆向量 |
| 记忆 token | 写入输入末尾放置 $S=[s_1,\ldots,s_k]$，训练其输入 embedding，并在各段复用；实际保存的是这些位置的末层隐藏状态 $Z_t$，不是输入 embedding |
| 记忆 embedding 初始化 | 统一逐元素独立采样 $E_{ij}\sim\mathcal N(0,0.02^2)$，即均值为 0、标准差为 0.02；$E\in\mathbb R^{k\times d}$ 为可训练的记忆 token 输入 embedding 矩阵 |

记 $C_\theta(\cdot)$ 为上述写入过程：输入待处理内容，附加 $S$，取出新记忆块。读取端使用更新后保存的全部记忆；写入端是否读取历史，不限制读取端的范围。

| 方法 | 特有实现细节 |
|---|---|
| ICAE-single | 仅在完整原文处于单次训练长度与上下文窗口内比较 |
| ICAE-multi | 各段独立写入，拼接全部输出块后读出；训练需包含多段拼接读出样本 |
| AutoCompressors | 每次写入输入新段与累计记忆，生成新块后追加到已有记忆末尾 |
| 按记忆变化扩容 | 先生成覆盖候选并打分，触发扩容时再生成追加候选；两种候选的写入方式见第 1.3 节 |
| 按信息损失程度扩容 | 分别生成两种候选，暂用固定历史 QA 的答案 NLL 评估损害与收益；带答案的决策仅作为离线 oracle 参照，测量方式后续可替换 |

训练安排：

- **三种基线**：各自的训练目标及样本组织见第 3 节。
- **两种动态方法**：采用第 3.3 节的三阶段训练，对照时固定写入实现与训练目标，分别更新各自参数。不同写入实现作为后续架构对照。

### 1.3 两种动态方法的四种写入实现

覆盖候选 $Z_t^{\rm rw}$ 需要承接 $A$ 的旧信息并吸收新原文 $X_t$，追加候选 $Z_t^{\rm app}$ 主要保存 $X_t$。两者均为 $k\times d$ 的记忆块，按各自动作生成，更新方式如下：

| 情况／动作 | 写入后的记忆 | 含义 |
|---|---|---|
| 首段 | $[Z_1]$ | 由 $X_1$ 建立初始记忆，不作扩容判断 |
| 覆盖 | $[P,Z_t^{\rm rw}]$ | 只替换末块，容量不变 |
| 追加 | $[P,A,Z_t^{\rm app}]$ | 保留旧块并增加 $k$ 个 slots |

四种实现通过输入范围、动作标记、attention mask 或 LoRA 参数区分两种动作。**首轮采用版本 1**；其余版本按后续实验需要实现。每一种实现都可配合两种动态决策依据。

| 版本 | 追加候选 | 覆盖候选 | 动作区分方式与主要考虑 |
|---|---|---|---|
| 1．局部输入 | $C_\theta(X_t)$ | $C_\theta(A,X_t)$ | 通过输入范围区分；不输入更早记忆 $P$，实现最简单 |
| 2．完整历史＋动作标记 | $C_\theta(P,A,X_t;\mathrm{app})$ | $C_\theta(P,A,X_t;\mathrm{rw})$ | 两种动作均读取完整历史，用显式动作标记说明输出用途；历史可辅助理解，也可能混入输出 |
| 3．完整历史＋注意力限制 | $C_\theta(P,A,X_t;\mathrm{mask}_{\rm app})$ | $C_\theta(P,A,X_t;\mathrm{mask}_{\rm rw})$ | 用 attention mask 区分直接压缩范围，允许其余历史间接参与；具体路径见下表 |
| 4．两种动作分别使用 LoRA | $C_{\theta_{\rm app}}(P,A,X_t)$ | $C_{\theta_{\rm rw}}(P,A,X_t)$ | 共享冻结基座与读取端，以不同 LoRA 区分动作；用于检验共享适配参数是否存在任务干扰，但增加可训练参数 |

版本 3 的输入序列为 $[P,A,X_t,S]$。“直接读取”指 **$S$ 位置作为 query 时，哪些输入位置的 key/value 可以参与 attention**，不是解码器读取记忆的范围。

| 生成目标 | $S$ 可直接关注的内容位置 | 被屏蔽的历史位置 | 历史影响新记忆的路径 |
|---|---|---|---|
| 追加 | $X_t$ | $P,A$ | $P,A$ 经由 $X_t$ 的中间表示间接传递 |
| 覆盖 | $A,X_t$ | $P$ | $P$ 经由 $A$ 或 $X_t$ 间接传递；$A$ 同时具有直接路径和经由 $X_t$ 的间接路径 |

- 每一层都执行上述屏蔽；$S$ 内部保留自身及前序位置的因果连接，其余位置使用普通因果 attention。因此 $X_t$ 仍能利用完整历史理解当前文本。
- 间接路径跨不同层传递信息，不是额外执行一次压缩。历史输入在前向计算中产生各层隐藏状态，但只有新块被写回；应保留的旧记忆向量不变。
- 这一设计借鉴 [Anchor 的 attention mask](https://arxiv.org/html/2402.07616v2#S3.S2)，将其连接思路用于 token memory 的追加／覆盖；不沿用其 anchor KV 存储形式。mask 只限制信息路径，不保证消除旧内容重复或完整保留目标信息。
- mask 本身传入了动作信息，可不额外使用动作 token；训练时也需采用相应 mask。完整历史仍参与计算，不能据此假定成本等同于局部版本。

## 2. 两种动态决策依据

### 2.1 按记忆变化扩容

先生成覆盖候选 $Z_t^{\rm rw}$。只为打分，对 $A$、$Z_t^{\rm rw}$ 的每个 slot 独立做无可学习参数的 RMS 归一化：

$$
N(B)_{ij}=\frac{B_{ij}}{\sqrt{d^{-1}\sum_{j'=1}^{d}B_{ij'}^2+\epsilon_N}},\qquad
I_t=\frac{\lVert N(Z_t^{\rm rw})-N(A)\rVert_F}{\lVert N(A)\rVert_F+\epsilon_N}.
$$

$I_t\geq\tau_I$ 时，按追加路径另行生成 $Z_t^{\rm app}$ 并保存 $[P,A,Z_t^{\rm app}]$；否则直接保存 $[P,Z_t^{\rm rw}]$。实际存储和读取仍使用未归一化的记忆。

该分数受 [DLA 的状态变化门控](https://arxiv.org/html/2606.10650v1)启发，但当前比较的是**尝试覆盖后与覆盖前的末块表示**，不是直接照搬其线性状态更新公式。它衡量对应 slot 的表示变化，**不能直接解释为遗忘或信息增量**；RMS 归一化也不能消除 slot 内容对应关系变化带来的影响。

### 2.2 按信息损失程度扩容

这里的“信息损失”指更新后旧信息的可读性下降，不预设必须用问答衡量。本实验暂用少量历史 QA 的答案 NLL 估计损失，并检查追加能否缓解；后续可替换这一测量方式。

数据构造时，为每条轨迹的每个更新点 $t$ 固定 $q=8$ 道历史问题，记为 $Q_t^{\mathrm{gate}}$：证据位于 $X_{<t}$，答案未被 $X_t$ 修订，历史位置分配见第 3.1 节。每次更新分别生成 $Z_t^{\rm rw}$、$Z_t^{\rm app}$，直接用这批题评估更新前与两种实际候选记忆；评分只输入记忆、问题和标准答案，不回填历史原文。$L_t(B)$ 为先按答案 token、再按问题平均的 NLL。

$$
\begin{aligned}
L_0&=L_t(M_{t-1}),\\
L_{\rm rw}&=L_t([P,Z_t^{\rm rw}]),\\
L_{\rm app}&=L_t([P,A,Z_t^{\rm app}]),\\
d_t&=L_{\rm rw}-L_0,\\
g_t&=L_{\rm rw}-L_{\rm app}.
\end{aligned}
$$

| 量 | 解释 |
|---|---|
| $d_t>0$ | 覆盖使旧问题更难回答；数值越大，损害越大 |
| $g_t>0$ | 追加比覆盖更有利于旧问题 |
| $d_t-g_t=L_{\rm app}-L_0$ | 追加后的残余损害；追加较好不代表已恢复旧信息 |

决策规则为

$$
\text{追加}\quad\Longleftrightarrow\quad
(g_t>\tau_g)\ \lor\ (d_t>\tau_d\ \land\ g_t>\eta),
\qquad 0\leq\eta<\tau_g.
$$

覆盖损害很大时，允许较小但实际为正的追加收益；不能仅因 $d_t$ 大就假定追加一定有益。$L_0$ 用于计算本次更新造成的变化，其绝对值另作诊断；更新前已有的高损失本身不算本次覆盖损失。门控问题与评估问题按事实或证据划分，不使用同一事实的改写问题充当独立测试。

## 3. 训练流程与数据设置

### 3.1 通用训练概念与设置

| 训练目标 | 读取端完成的任务 | 监督信号 |
|---|---|---|
| AE：原文重建 | 根据压缩记忆恢复被压缩的文本 | 原文本身 |
| LM：文本续写 | 根据压缩记忆预测未输入压缩器的后续文本 | 原文的后续部分 |
| QA：问答 | 根据压缩记忆和问题生成答案 | 标准答案 |

上述目标均以 teacher forcing 计算目标序列的交叉熵：预测当前位置时使用此前的标准目标 token。问题和训练答案不作为写入器的额外输入。

| 通用设置 | 约定 |
|---|---|
| 初始化与阶段衔接 | 记忆 embedding 在基础训练开始前按统一标准初始化；后续阶段继承已有 LoRA 和 embedding，继续训练 |
| 数据划分 | AE＋LM 与 QA 使用不同来源文档，均继承 FineWeb 原文档簇的 train／dev／test 划分；各方法在相应划分内组织样本，测试采用统一文本边界 |
| 任务 QA | 每段 4 道；train 中用于反向传播，dev／test 中作为评估 QA |
| 门控 QA | 仅用于信息损失策略的动作评分；每更新点预先固定 8 道历史题，保留证据并检查答案在使用位置仍成立 |
| 题池隔离 | 同一轨迹的任务题与门控题按事实分开，同一事实的改写不计为不同事实；两种动态方法使用相同任务题 |
| 预训练文本 | 基础 AE＋LM 复用已有 FineWeb 来源与划分，按各方法的写入长度组织；动态方法阶段①仍使用单段原文 |

**QA 轨迹的文本规格**

阶段②、阶段③和统一评估采用 6–10 段的连续原文轨迹，总长 18,432–40,960 字符（粗估 4,608–10,240 tokens）。构造时按英文每 4 个字符约 1 token 估算，直接计原文字符数，包含空格与换行，不加载 tokenizer；不含问题、答案、提示和记忆 token。训练时使用基座正常分词并记录实际长度，保留已经标注的原文与边界。

| 项目 | 当前设置 |
|---|---|
| 每条数据 | 同一来源文本的一条有序轨迹，随机 $T\in[6,10]$ 段 |
| 更新次数 | 首段建立记忆，随后 $T-1$ 次追加／覆盖决策 |
| 每段原文 | 3,072–4,096 字符内随机抽样，粗估 768–1,024 tokens；允许任意字符边界 |
| 整条原文 | 18,432–40,960 字符，粗估 4,608–10,240 tokens |
| 基座窗口 | 须容纳实际分词后的完整原文、记忆 token 和写入提示；优先选择支持 16k 或更长上下文的基座 |
| 基线适配 | ICAE-single 的完整历史压缩训练覆盖实际长度；ICAE-multi 包含 6–10 块拼接读出；AutoCompressors 保留原定 LM 目标与训练分段方式 |

各方法的 QA／评估使用同一文本和边界。分段规则先于题目分配确定，不根据模型动作调整，也不通过拼接无关文档补足长度。QA 从 FineWeb 原候选池中排除已有三组 AE／LM 数据的来源及其去重簇，再读取剩余文档的连续长原文、离线生成并核验 QA；即使已有数据只使用短片段，也按整篇文档排除。旧服务器核查的旧池内剩余来源为 82,402 篇；本地当前采用保守排除整个旧 100,000 篇候选池的口径，从池外取样。现行接口与长度依据见[数据构造流程](20260928_fineweb_qa_construction.md)，旧来源调查见[数据调研第 2.1 节](20260927_step1_qa_data_survey.md)。来源池在批次标注前统一冻结，之后按批次编号选择不重叠切片；train/dev/test 使用同一构造协议，任务题分别承担训练或评估角色。6–10 段数据协议已完成离线实现，真实首批待用户检查后启动。

**每条轨迹的 QA 配额与使用**

| 原文段 | 任务题 | 门控题 | 不同题目合计 |
|---|---:|---:|---:|
| $X_1$ | 4 | 8 | 12 |
| $X_2$–$X_{T-1}$，每段 | 4 | 4 | 8；共 $8(T-2)$ |
| $X_T$ | 4 | 0 | 4 |
| 整条轨迹 | **4T** | **4T** | **8T（48–80）** |

- 首轮优先使用有明确证据的短答案事实题，参考答案以 1–12 个英文词为目标，构造上限为 128 字符（估算约 32 tokens），不截断答案。每段配额中的题，其完整证据位于该段；数据准备时检查答案在后续使用位置仍成立。
- **门控**：第一次更新使用 $X_1$ 的 8 道门控题；之后使用上一段的 4 道题及更早历史的 4 道题。更早题按历史位置分散选取，并在不同更新点轮换；无需每一步覆盖全部旧段。
- **训练**：首段使用 4 道新题；每次更新使用当前段 4 道新题与历史 4 道旧题。第一次更新的旧题均来自 $X_1$，之后默认上一段 2 道、更早历史 2 道。旧题从已有任务题中复用，损失仍按实际题数平均。
- **评估**：dev／test 使用相同的两类题池结构，任务题作为评估题，不再额外准备训练题。最终评估全部 $4T$ 道任务题，分别报告前 $T-1$ 段旧信息 $4(T-1)$ 题、末段新信息 4 题及总体结果；中间评估使用所有已读入段的任务题。
- “上一段”指原文段，不是最后一个记忆块。题目 ID 与各更新点的分配离线固定，不按运行时记忆能否回答筛题。

**数据格式与规模预期**

按 JSONL 保存，一行一条轨迹；每道 QA 保存一次，各更新点通过 ID 引用。

| 内容 | 保存的信息 |
|---|---|
| 来源与文本 | 来源文档 ID、来源文本范围、划分、轨迹原文和分段字符边界 |
| QA 池 | 题目 ID、问题、参考答案、完整证据位置、事实组和任务／门控归属 |
| 更新点 | 固定的门控题、新任务题、旧任务题 ID；不预存追加／覆盖动作 |

| 数据规模预期 | train 轨迹 | dev 轨迹 | test 轨迹 |
|---|---:|---:|---:|
| 首轮 | 500–1,000 | 50–100 | 100–200 |
| 扩大训练 | 3,000–5,000 | 200–300 | 300–500 |

首轮训练争取覆盖至少 200 篇独立来源文档，扩大后至少 1,000 篇；首轮测试争取至少 50 篇。每条为 $8T=48$–$80$ 道不同 QA；按实际段数求和报告，包含任务与门控题，另计 dev／test。按实际不同题目 ID 统计，重叠窗口和重复读取不算新增标注。

这些是数据准备目标，不是现有数据的已验收数量。可复用 [SQuAD 轨迹代码](../../src/latent_working_memory/v1/dynamic/squad.py) 的来源与证据组织；候选数据是否满足长度、各段题量及事实隔离要求，见 [数据调研](20260927_step1_qa_data_survey.md)。

### 3.2 三种基线的训练设置

| 基线 | 训练流程与目标 | 样本组织及反向传播 |
|---|---|---|
| [ICAE-single](https://arxiv.org/html/2307.06945) | AE＋LM 预训练，再做指令微调 | 每个样本一次压缩完整上下文，读取其记忆计算目标损失 |
| [ICAE-multi](https://arxiv.org/html/2307.06945) | 延续 ICAE 的预训练与指令微调流程 | 加入各段独立压缩、拼接全部记忆后读出的样本；损失回传到各段写入。多段样本的加入阶段与配比待定 |
| [AutoCompressors](https://arxiv.org/html/2305.14788#S3.SS1) | 对全文做下一 token 预测 | 训练时随机分段，利用累计记忆预测新段，再追加摘要；采用跨段反向传播，在两个压缩步骤后停止旧记忆的梯度 |

### 3.3 两种动态方法的三阶段训练

两组采用相同的写入版本、训练数据、损失和优化设置，首轮使用局部写入。暂定以下三阶段流程；**第二阶段先保留，后续通过效果与消融决定是否缩短或移除**。

| 阶段 | 学习内容 | 输入与动作安排 | 训练目标 |
|---|---|---|---|
| ① 基础压缩预训练 | 将原文编码成冻结读取端可利用的记忆 | 单段原文经 $C_\theta(X)$ 生成记忆；不进行扩容判断 | AE＋LM，混合比例待定 |
| ② 追加／覆盖预热 | 从自身生成的记忆继续更新，学习两种动作 | 首段建立记忆，后续更新暂按各 $1/2$ 概率采样追加或覆盖 | 更新后记忆上的 QA |
| ③ 动态策略训练 | 适应各自扩容规则产生的记忆轨迹 | 按第 2 章规则选择动作，将实际保存的记忆传入下一更新点 | 与阶段②相同的 QA |

阶段①可生成两个动态方法共用的初始 checkpoint；两组各自加载后独立执行后续训练。阶段②使用相同的预热日程和动作采样设置，不固定每条轨迹的追加次数；阶段③的差异来自门控规则及其产生的轨迹。

**阶段②与③的 QA 损失**

记 $Q_t^{\mathrm{old}}$ 为本次实际参与计算的旧信息训练题，证据位于 $X_{<t}$，覆盖上一段及更早历史；$Q_t^{\mathrm{new}}$ 为本次实际参与计算的新信息训练题，证据位于当前段 $X_t$。训练答案均需在当前前缀 $X_{\le t}$ 下成立。使用实际保存的记忆 $M_t$，对全部题目的损失取均值：

$$
\mathcal L_t=
\frac{
\sum_{(q,a)\in Q_t^{\mathrm{old}} \cup Q_t^{\mathrm{new}}}\ell(M_t;q,a)
}{|Q_t^{\mathrm{old}}|+|Q_t^{\mathrm{new}}|}.
$$

- $\ell(M_t;q,a)$ 为单道题按答案 token 平均的 NLL；每道题权重相同，新旧题的总权重由各自实际题数决定。首段只对新信息题取均值。
- 读取端根据 $M_t$ 和问题预测答案；两组使用相同的训练题和损失归约方式。
- 阶段②只计算采样动作对应的写入和 QA 损失；阶段③只对实际选中的记忆状态计算训练损失，未选中候选不另加辅助损失。

**阶段③的更新与反向传播**

1. 按各动作路径生成所需候选，以第 2 章的门控规则选出 $M_t$。
2. 门控评分与离散选择不求梯度；在选中的 $M_t$ 上计算 $\mathcal L_t$，保留其到写入器的梯度。
3. 将 $M_t$ 传入下一更新点，训练过程中始终使用模型自身逐步生成的记忆。
4. 本轮 6–10 段轨迹暂采用完整展开：同一轨迹内保持参数不变，对各步损失取平均后反向传播并更新参数。先按完整轨迹实测显存，确定 microbatch 与问题批处理设置。

门控 QA 不直接提供反向传播损失，但会通过动作选择影响后续训练。两组各阶段使用相同的训练样本量与优化步数，额外门控耗时单独统计。阈值作为阶段③的训练配置，按开发集质量与容量选择；不同阈值配置分别进行策略训练。

**成本与诊断**

| 方法 | 阶段③每个更新点的候选生成 | 门控额外计算 |
|---|---|---|
| 按记忆变化扩容 | 先生成覆盖候选；触发追加时再生成追加候选 | RMS 归一化与表示距离 |
| 按信息损失程度扩容 | 分别生成覆盖和追加候选 | $q$ 道问题在更新前及两种候选下的 NLL，共 $3q$ 个问答实例 |

- 每条轨迹的训练问答读取为 $4+8(T-1)=8T-4$ 次，T=6–10 时为 44–76 次。阶段②和记忆变化组的阶段③采用相同安排。
- 信息损失组阶段③另需 $3q(T-1)=24(T-1)$ 个门控评分实例，合计 $32T-28$ 个问答实例／轨迹（T=6–10 时为 164–292），候选写入与独立评估另计。实例可批处理，不等于独立模型调用次数；原始标注为 $8T$ 道不同题。
- 记录两种动作的触发比例、新旧训练题损失、连续覆盖后的表现及门控题的 $L_0$ 分布；$L_0$ 普遍偏高时检查基础压缩与读出能力，不临时筛题。
- 先用少量正式长度轨迹实测时间与显存，再确定 batch 与训练步数。分支与问题可批处理；$L_0$ 只在模型参数、记忆及题目相同时复用。
- 测试时若继续使用标准答案决定动作，结果标为带答案的离线 oracle 参照。

## 4. 评估与进入第二步的条件

- **质量**：评估 QA 的旧事实、新段事实和全历史结果；按事实距当前段的位置分层，同时报告答案生成指标与 NLL。门控题的 $L_0$ 分布另作诊断，不用于筛题。
- **容量**：最终 slots、轨迹平均 slots、追加／覆盖次数；不强制动态方法追加相同次数。ICAE-multi 与 AutoCompressors 的逐段追加固定占用 $Tk$，是高容量参照点；ICAE-single 占用 $k$，但仅适用于长度范围内的历史。
- **计算**：写入、读出和门控的时间／计算量分开记录。主要比较动态策略在相近最终及过程容量下的质量，也检查新信息表现是否相近。
- **判定**：若“按信息损失程度扩容”在多个容量点稳定优于“按记忆变化扩容”，且收益不能由更多记忆或牺牲新信息解释，再进入“运行时预测损害”的第二步；否则停止这一路线。

## 5. 代码实现范围

| 位置／职责 | 最小实现内容 |
|---|---|
| `src/latent_working_memory/v3/`：轨迹与 QA | 分块、每个更新点固定的门控题集、历史证据校验与评估题隔离、更新次数上限 |

| 同目录：方法与训练 | 三种基线按各自流程训练；动态方法依次执行 AE＋LM 预训练、QA 动作预热和 QA 策略训练；门控无梯度评分与选中路径训练分开 |

完整历史＋动作标记、注意力限制、分别使用 LoRA 三种版本按后续实验需要实现，当前不预置全部分支。现有 v2 的读写／NLL 接口和实验记录方式可借鉴，但其 [pooling、固定容量的 codec](../../src/latent_working_memory/v2/memory_codec.py)不能直接当作本实验的 gist-token 写入器。正式编码前仍需定下支持本轮长度的基座型号、LoRA 配置、各阶段数据配比与训练步数、记忆块大小 $k$ 及具体数据来源；轨迹和 QA 数量按第 3.1 节执行。
