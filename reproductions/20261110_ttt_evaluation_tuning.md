## 单卡测量与验证标准

在 `zcy-memory` 单张 A800-SXM4-80GB、物理 GPU 0 上测试。三个方法顺序独占该卡，显式设置 `CUDA_VISIBLE_DEVICES=0`、`OMP_NUM_THREADS=1`、`MKL_NUM_THREADS=1`；checkpoint、生成预算、任务及正式数据规模不变。本轮只做优化验证与选参，没有正式全量 benchmark 分数。

当前入口已支持多卡样本分片，此次仅做静态审查，未实测多卡吞吐。下文的参数测量与耗时估计均针对单卡；双卡命令及每卡参数含义见各方法 README。

本文件中 E²-TTT 的参数和估时针对原始 B1 实现及同卡多进程并发；本地批量推理的测量单独见[批量推理记录](20261110_e2_ttt_batch_inference.md)，当前命令以方法 README 为准。

用户确认的批处理标准是：**原公式、更新时序和样本隔离不变，允许浮点舍入引起少量生成差异**。完整 token IDs 是否一致仍独立记录，不把数学定义相同写成任意输入逐 token 相同。

## LaCT 的真实 batch

原增量优化已经保存了每条样本的 fast weights，只是 attention 调用与输入检查限定 B1。现在 attention 仍调用原 `flash_attn_varlen_func`，将 Q／K／V 从 `[B,L,H,d]` 展为 `[B×L,H,d]`，用 `[0,L,2L,…,BL]` 标记序列边界；基础模型参数共享，KV 和 `B×heads` fast weights 逐样本独立。`ttt.py` 与上游源码未修改，读出、Momentum、归一化及写入公式均保留。

批内输入的真实 token 数必须完全相等，因此可共用进度计数与 chunk 相位。前缀长为 L 时，更新次数仍为 `floor((L-1)/2048)`，满尾段在下一 token 到来时才提交。

评估入口增加 `--batch-size`，默认仍为 1，正式 Momentum 命令推荐 16。同一 RULER 长度内跨六任务按精确 token 数分组，不改文本、不截断，prefill 不加 padding、不复制样本；尾批按实际大小运行。保留原样本 ID 和任务，按各行首个 EOS 裁掉补齐部分，评分与续评仍覆盖全量 12,000 条。EOS 后的已停止行可在 HF 批内继续占位计算，其状态不再使用且不跨题复用，不影响其他行。

### 数据分组与吞吐

完整数据的 CPU tokenizer 统计耗时约 152 秒：四档各 3,000 条，分别有 50／61／62／68 种真实 token 长度。上限 B8 时平均实际 batch 为 7.444，93.13% 样本进入完整 B8；上限 B16 时平均实际 batch 为 13.559，86.93% 样本进入完整 B16，总计 885 个实际批次。

### 一致性与隔离

- 原生 32K 候选 B2／4／8／16 均有 15/16 条完整生成 IDs 与 B1 一致；逐题原生评分均为 16/16 一致。这只是小样本诊断，不是正式 benchmark 准确率结论。4K 结果：B2／4／8／16 的 16 条完整 IDs 均与 B1 相同，逐题评分也全部相同。
- 对产生差异的同一输入做固定参考续写：首层相同输入的 LR／Momentum／scale 小投影已出现 BF16 舍入差异；首次预测分歧处，两个候选 logit 在 B1 下相差 0.125，在批量下变成并列。这是实际定位到的数值来源，不能把全部差异归结为最后的词表投影。
- 同形状的强隔离检查固定 B4 目标样本的输入、槽位和参考续写，只交换其他三个同行。prefill 与四步续接共 5 次检查中，目标 logits、逐层 KV、fast weights、范数、Momentum 和 pending 缓冲均逐字节一致，两条路径的更新进度也一致。
- 2047／2048／2049-token 连续真实窗口覆盖跨 chunk 边界。45/45 个状态检查的结构、dtype、有限值与更新进度通过；210 个逐样本教师强制 argmax 中 208 个一致。该测试的原严格结果保留为未通过，不改写为完全相等。边界探测触发过 `_ttt_read` 编译缓存上限告警，发生在吞吐计时以外。
- EOS 控制检查使用明确标记的临时停止 token，一行生成 1 token 后停止、其他行继续，裁剪后的结果与逐条对照一致。正式评估仍使用 checkpoint 自带 EOS。

尝试过只将小投影逐样本执行，以保留 B1 GEMM 形状；它未消除全部生成差异，32K B16 吞吐降到 0.5187 条／秒，因此未保留该方案。最终使用原生批量矩阵计算，不加入人工通道、额外目标或精度切换。

## 完整评估时间

LaCT 按完整分组直方图计算，不能简单采用 `12000 / B16吞吐`：每档中实际大小为 b 的批次数为 n(L,b)，则生成时间为各档 `sum_b n(L,b) × T(L,b)`。T 使用实测的 B1／2／4／8／16 单批时间；尾批大小在相邻实测 B 间线性插值，8K／16K 在 4K／32K 间按输入长度插值。CPU tokenizer、载入、首次编译、解码与评分另留余量。

上限 B8：生成约 5.291 小时，加 CPU 预处理约 5.333 小时；上限 **B16：生成约 3.309 小时，加 CPU 约 3.351 小时**。正式运行推荐 B16，按 20–25% 的载入、首次编译和评分余量，建议预留 **4–4.5 小时**。8K／16K 是插值估计，未作为独立 GPU 吞吐点测量。五个 checkpoint 单卡顺序执行的外推主体合计约 **151.6 小时，6.3 天**，主要时间仍来自两个 In-Place checkpoint。

E²-TTT 每模型仍为两项六长度 RULER 6,000 条，加 SQuAD 2,984 条、SWDE 1,111 条，共 10,095 条。按八个原生 job 的排队事件估算，保留 RULER 16K→512、SQuAD、SWDE 顺序，计入最后不足满并发的时间：MLP／SwiGLU 为 5.42／5.26 小时，建议各预留约 4–7 小时。

In-Place TTT 每模型七档各 1,300 条，共 9,100 条，逐长度采用真实单进程均值外推：TTT／baseline 为 68.92／68.62 小时，建议约 59–80／58–79 小时。256K 本身约占 45.9／45.7 小时，无法仅靠并发参数压到半天。

这些范围是小样本的规划余量，不是统计置信区间；假定 GPU 独占、当前环境与生成设置不变。不同方法的生成预算和模型不同，不据此直接比较算法效率。

## 历史并发对照与记录

此前 B1 独立进程测试共 34 组计划、53 个计时 trial；19 组并发配对累计 212 条生成序列的 IDs 全部一致，包含候选间重复输入。原始结果保留在 `artifacts/reproductions/evaluation-tuning_20261110/measurements.json`，最终当时设置在 `selection.json`；其中 LaCT 八进程已由本轮单进程批处理设置替代。

- LaCT 32K 的 W1／2／4／8 为 0.0999／0.1879／0.3191／0.3513 条／秒。
- E²-TTT 16K：MLP W1／2／4／6 为 0.1053／0.1553／0.2191／0.2185；SwiGLU 为 0.1048／0.1466／0.1978／0.2178。6 与 4 进程使用 N12／N8，不是完全相同语料的严格加速比。MLP 取 4；SwiGLU 本轮取 6。
- In-Place TTT 128K 双进程占用约 75.8／77.4 GiB，TTT／baseline 整池反而慢约 10.0%／9.2%，因此取单进程。
